# Wanderlust2 — Coding Standards & Project Instructions

## Architectural Constraints
- **Single Responsibility**: One class/module per file.
- **Design Patterns**: LangGraph StateGraph for pipeline orchestration; Factory-style recommender init.
- **Performance**: Haversine in O(n); vector search via ChromaDB ANN; weighted scoring in O(n).

## File Organisation
- Execution sequencing: `app.py` (00_main) → `db.py` (01_db) → `recommender.py` (02_recommender).
- `docs/` — All documentation, README, and drawio diagrams.
- `scripts/` — Build and run shell scripts.
- `backend/` — Python API and AI pipeline.
- `components/`, `services/` — React frontend modules.

## Naming Conventions
- Python: PEP 8 (snake_case functions, PascalCase classes).
- TypeScript: camelCase functions, PascalCase components.

## Documentation Rules
- README and all docs live exclusively in `docs/`.
- Every code change must be reflected in `docs/README.md`.
- Diagrams (HLD, LLD, flow, UML) are maintained in drawio format inside `docs/`.

## Git Hygiene
- `.gitignore` covers node_modules, __pycache__, venv, dist, *.sqlite3, chroma_store, .env.
- No build artifacts or temporary files tracked.

## Build & Run
```bash
cd wanderlust2
chmod +x scripts/*.sh
./scripts/build.sh
./scripts/run_backend.sh   # port 5001
./scripts/run_frontend.sh  # port 3000
```
